## 0. Непреложное правило: ничего не теряем функционально

Макеты закрывают **пользовательскую (consumer) часть** — это приоритет визуала.  
**Все возможности всех ролей должны остаться:** guest, клиент, dealer, moderator, admin.

| Формулировка | Значение |
|---|---|
| Staff /admin «вне пиксельного макета» | Не перерисовываем layout/логику `/staff/*` по consumer-макету. **Не удаляем и не ломаем** staff UI, API-вызовы, role-gates, виджеты. В v1 на staff **подключаем** общий `SiteHeader` + токены (см. §5). |
| Cut-list макета (Журнал, ИИ, PDF…) | Не добавляем *новые* продуктовые сущности из макета. Существующий функционал **не вырезаем**. |
| Док «+» у dealer/admin | **Оставляем** привычный путь в доке (см. §5). |

**Инвентарь, который обязан жить после v1 (минимум):**

- Все маршруты `/staff/*` (listings, requests, admin-*, import-plan, import-candidates, search-profiles, publish-*).
- Role-gated блоки на `/` (parser/admin и т.п.) — **оставляем на главной под витриной** (решение 1A).
- Staff-блоки в профиле — **всегда видны** под consumer-меню для соответствующих ролей.
- Auth/PIN/passkey, чаты, заявки, избранное, калькулятор, FAQ — без регрессии для клиентов.
- Dealer: открытые заявки, офферы, чаты, свои объявления + «+» в доке.
- Admin/moderator: модерация, бренды, FAQ CMS, customs coeffs, users, parser jobs, sourcing/agent tooling.

Каждый PR редизайна: чеклист «роли guest / client / dealer / staff — smoke существующих сценариев».

## 1. Cut-line v1 (scope)

### Рестайлим (реальные данные, существующие API)

| Поверхность | Маршруты / компоненты |
|---|---|
| Chrome: токены, header, dock, footer | `_app.js`, `globals.css`, новый `SiteHeader`, `MobileBottomNav`, `SiteFooter` |
| Главная-витрина | `/` (новый состав) |
| Каталог + фильтры (chip sheets) + sort | `/catalog/[[...slug]]`, `CatalogQuickFilters`, cards |
| Карточка авто + breakdown + trim sheet | `CarDetailView`, lightbox |
| Auth / register / PIN / AppLock | `auth.js`, `PinSetupPanel`, `AppLockGate`, `AuthPromptModal` |
| Чаты list + thread | `messages.js` |
| Заявка | `request-quote.js` (структурированные поля → упаковка в `comment` при необходимости) |
| Калькулятор | `customs-calculator.js` |
| FAQ | `faq.js` (+ UI-разделение «общее / Китай» на статике/фильтрах без CMS) |
| Избранное | `favorites.js` |
| Профиль-хаб + мои заявки + мои данные + безопасность (пароль/PIN/passkey) | `profile.js` |

### Soft-shell (UI есть, без новых API; пусто / static / local)

| Поверхность | Поведение v1 |
|---|---|
| «Ваша сделка» на главной | Если есть активная заявка (`GET /requests/my`) и/или platform chat — карточка-ссылка на чат/заявку. Иначе блок скрыт. |
| Мои заявки (deep) | Ремаппинг существующих `CalculationRequest` + offers, UI как в макете. |
| «Сделка и документы» | **Не отдельный раздел.** Статусы/ссылки живут в заявке + чате. Пункт профиля не ведём на фейковые PDF. |
| Сохранённые расчёты | **Вырезаем из навигации профиля.** Калькулятор без «сохранить в кабинет». (localStorage — только если появится явный follow-up.) |
| Уведомления | **Вырезаем центр.** Бейджи unread на чатах/заявках как сейчас. |
| Журнал | **Вырезаем** из главной и header в v1. Не заводим `/journal`. |
| Empty / loading / error states | Делаем по макету на каталоге, избранном, чатах. |
| Гостевые гейты | Рестайл `AuthPromptModal` + CTAs «заявка без входа». |

### Вырезаем из v1 (фаза 2 / backend)

- Гостевой ИИ-консультант и handoff менеджеру (виджет не показываем).
- PDF документов сделки (договор, диагностика, инвойс, ЭПТС).
- In-app notification center + настройки каналов.
- «Ниже рынка» badge.
- Цена «под ключ до вашего города» с пер-city пересчётом (показываем существующий `estimated_total_rub` как «под ключ», город — из профиля/Москва по умолчанию только в copy, без ложного расчёта).
- Data-driven диагностика / история АТС / видео-осмотр / трекинг (см. §3).
- **Визуальная** перерисовка layout/логики `/staff/*` «как consumer-макет» — нет; функции **сохраняем**; `SiteHeader`+токены — да (§5). Native apps — вне цикла.

### Критерий done v1

«Ключевые consumer-экраны выглядят и навигируются как макет **на существующих данных**».  
Плюс: **нулевая функциональная регрессия** для guest / client / dealer / moderator / admin (см. §0).  
Не цель: интерактивность всех 34 экранов макета.

## 2. Ответы на открытые вопросы sync brief

### Scope и продукт

1. **Жёсткость FE-only:** Журнал / ИИ / сделки+PDF / уведомления / saved calcs **не входят** в v1 (не кликабельные пустые оболочки, кроме «Ваша сделка» = живая заявка/чат).
2. **«Сделка»:** ремаппинг `CalculationRequest` + platform/dealer chat. Отдельной entity Deal не ждём в v1.
3. **Главная vs Каталог:** отдельная витрина на `/`, listing на `/catalog` (и SEO slug-дерево без изменений). С `/` можно deep-link фильтрами только через переход в каталог.
4. **Док:** 5 вкладок consumer: Главная · Каталог · Чаты · Избранное · Профиль. Гость: Чаты/Избранное → гейт; 5-я вкладка «Войти». У **dealer/admin «+» / Новое объявление в доке оставляем** (привычный путь).
5. **ИИ:** out of v1 полностью (ни виджет, ни embed).

### Дизайн-покрытие

6. **Desktop:** catalog + detail по макетам 33–34; остальные страницы — те же токены/компоненты, без ожидания дорисовки.
7. **SoT:** HTML-bundle в `design/mockups/`. Figma/отдельный token file пока нет — токены извлекаем из макета в CSS `:root`.
8. **Native:** только web в этом цикле.

### Контент и данные

9. **«Что проверяем»:** маркетинговый copy-блок на карточке (статичный), без обещания «открыть отчёт» если файла нет. CTA «по заявке» / «в чат», не фейковые PDF.
10. **«Ниже рынка» / city turnkey:** скрываем badge; city-specific price не имитируем.
11. **Журнал:** не делаем в v1 (контент/хранилище — later).

### Технический каркас

12. **CSS:** эволюционный путь — токены + рефактор `globals.css` + shared components; **без** Tailwind/MUI в v1.
13. **PWA:** минимально — не ломать dock/safe-area под новый chrome; отдельный визуальный rework install prompt — later, если останется время в фазе chrome.
14. **SEO-лендинги:** позже той же системой токенов; не блокируют v1 catalog/home/detail.

## 3. IA карта маршрутов (mobile dock)

| Вкладка | Guest | Authed client | Staff/dealer |
|---|---|---|---|
| Главная | `/` витрина | `/` + блок сделки если есть | `/` + role-gated ops под витриной |
| Каталог | `/catalog` (+ SEO slugs) | то же | то же |
| Чаты | гейт → `/auth?next=/messages` | `/messages` | `/messages` |
| Избранное | гейт → auth | `/favorites` | `/favorites` |
| Профиль | label «Войти» → `/auth` | `/profile` | `/profile` + staff-блоки всегда под consumer-меню |
| (+) в доке | — | — | **Да** → `/staff/new-listing` (как сейчас) |

**SEO:** canonical `/catalog/...` и SSR каталога сохраняем. Home не должна воровать indexable listing URL без редирект-стратегии: listing filters живут на `/catalog`.

**Скрываем dock:** `/auth`, `/reset-password`, открытый thread `/messages?chat=…` — как сейчас; на `/staff/*` dock/footer — по текущим правилам `_app.js` (не ломать).

**SiteHeader:** consumer pages + staff pages (тот же логотип); body staff без перестройки форм/таблиц.

## 4. Out of scope явно (только «не делаем нового / не пикселим layout»)

- Backend schema / новые endpoints.
- Перерисовка внутренней логики/layout agent/import/search-profiles «как в consumer-макете» — нет; страницы и функции **остаются**; общий header/токены — да (§5).
- Native apps.
- Journal CMS, guest AI, deal documents, notification center (как *новые* фичи макета).
- Замена логотипа Avtovozom / favicon / отказ от логотипов марок в пользу плейсхолдеров макета.
